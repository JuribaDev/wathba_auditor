The per-target file-plan paths already exist in `buildFilesForTarget`; adapters join file-plan paths with resolution bodies (+ references/scripts from the raw skill) to produce the zip entries. Skills with missing values still render — the placeholder text is preserved in the body — so the Notice is the user-facing gate, not a hard block yet.
  - "Hard-block download until missing == 0" will land naturally with US-041 (browser zip). When the download button appears, disable it while `resolvedCatalog.hasMissing === true` and link the Notice to the review step via an anchor/scrollIntoView if we want to be pushier.
  - The resolver has no concept of "required" in the schema — all declared variables are implicitly required. If US-016 (freshness/governance metadata) wants to introduce `required?: boolean` so a skill can declare an optional variable, `isMissing()` is the single call-site to gate on that flag. I kept the check inline (not exported) so the behavior stays private to this module.
  - Placeholder regex intentionally restricts identifiers to `[A-Za-z][A-Za-z0-9_]*` — this matches the schema's variable name shape and prevents accidental capture of YAML-ish `{{ key: value }}` fragments or numeric braces. If a future skill body uses a different templating syntax (e.g., `{{skill.var}}` with a dot), the regex needs loosening but so does the variable-name contract in `@agent-skills/skill-schema`.
  - Boolean formatting uses `"true" / "false"` string literals. If a future skill wants locale-aware rendering ("yes" / "نعم" for a variable surfaced to end users rather than code agents), the formatter should move out of the resolver into the body itself via a different convention — the generated output is consumed by AI coding agents, so English literals are the right default.
  - The warning Notice shows the EN/AR skill name as the primary label and lists the raw variable names in mono font. We don't localize variable names (they're identifiers used in placeholders and must match). If UX wants human-readable variable labels in the warning, swap `entry.variables.join(", ")` to a lookup against each skill's `variables[i].label[locale]` — that data is already on `GeneratedSkill`, not threaded through `MissingVariables` today, so it'd need the catalog or a labeled missing entry.
  - `MissingVariablesNotice` is file-scoped to `step-generate.tsx`. Moving it to `components/ui/` only makes sense once a second caller needs it (e.g., if compare canvas previews gain a "missing" indicator).
